# 스캐닝 기반 판정 (SBOM 포함) — 요약 (2026-11-02)

> 담당: 스캐닝 Shadow 판정 + SBOM (YHC). 로그/Wazuh 판정은 별도 트랙.
> 상세·코드: `github.com/zeldaim/shadow-api-lab` (공개)

## 1. 판정 = 두 축을 "기준과 대조"

| 축 | 수집(스캔) | 기준 | 판정 결과 |
|---|---|---|---|
| **경로** | 능동 스캔 = 뭐가 열렸나 | `openapi.yaml`(명세) | 명세 밖 열림 → **Shadow API** |
| **부품** | SBOM = 뭘로 만들어졌나 | CVE DB | 취약 부품 → **취약 의존성** |

→ 둘 다 "**관측 ⊖ 기준**" 구조. 취약 여부와 무관하게 "명세 밖"이면 Shadow.
→ "열림"이 **실제로 취약한지**(예: BOLA·설정 유출)는 **Nuclei 커스텀 템플릿**으로 보조 확인.

## 2. 도구 선정 + 특성

| 역할 | 선정 | 왜 / 특성 |
|---|---|---|
| 디스커버리 | **ffuf** | 범용·빠름 → 기준선. (Kiterunner=API특화지만 공격적 필터로 누락, 참고용) |
| 취약점 스캔 | **Nuclei** ⭐ | YAML 커스텀 템플릿 → "열림"을 넘어 **실제 취약 증명**(debug/config 유출·v1 BOLA). 멘토 권장 |
| SBOM 생성 | **Syft** | 이미지·소스 → CycloneDX(표준). 스펙 1.5 고정(DT 호환) |
| CVE 대조 | **Grype** | Syft 짝, DB 내장 → 즉시 대조 |
| 지속 감시 | **Dependency-Track** | CycloneDX 전용 플랫폼, 대시보드·VEX·알림 |
| 판정 엔진 | **analyze.py**(자체) | 명세 ⊖ 스캔 → Shadow/Zombie 판정 |

→ 핵심 기준: 같은 사전이면 스캐너 정확도는 수렴 → **속도·사전 적합성**으로 선정.

## 3. 대시보드 흐름

```
[스캔 + SBOM]
     ↓  analyze.py (명세·스캔·부품 연관)
report.md (규칙기반)  ──►  app_dashboard.py (Streamlit 실시간 + LLM 보고서 버튼)
dashboard.html             ceo_dashboard.html (경영진 요약)
SBOM ──► Dependency-Track (취약 부품 지속 감시 대시보드)
```
- 내부망 밖으론 **수치만** → LLM이 문장형 보고서 → 경영진 대시보드 + 반복 점검.

## 4. 방화벽 이슈 (pfSense + WAF)

- 스택: **pfSense(L3/L4 + IPS) + WAF(ModSecurity/Apache)** → **스캐너 위치가 결과를 좌우.**
- 감사용 완전 목록 = **WAF 뒤 origin 직접 스캔**(WAF 우회). 외부 스캔은 공격자 시점 → 둘 비교.
- 스캐너 IP를 **pfSense 허용 + Suricata Pass List**에 등록(안 하면 차단돼 결과 오염).
- **획일적 403 = WAF 간섭** → "열림" 오탐 주의(차단 응답 보정 필요).
