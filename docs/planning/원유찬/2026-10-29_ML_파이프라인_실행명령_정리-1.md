팀 데이터는 `ml/data` 에 모아 두었으므로 **항상 `ml/data` 에서 실행**하세요.


## 2. 수집 시간 정하는 법

```
T-5분   시계 동기화(Windows "지금 동기화"), 팀원 IP·공격 PC IP 공유
T+0     팀원 6명 동시에 생성기 시작 (--duration 1200 = 20분)
T+3분   공격 시작 → attack_runs.csv 에 한 줄 기록 (시작 시각)
T+15분  공격 종료 (최소 5분) → 같은 줄에 종료 시각
T+20분  생성기 자동 종료
추출:   --start = T+0 - 1분,  --end = T+20 + 1분   (KST)
```

- 공격은 정상 트래픽이 도는 **구간 안에서만** 실행합니다.
- 공격 PC 에서 정상 생성기를 같이 돌리지 마세요.
- 같은 공격 PC 에서 도구 두 개를 겹쳐 돌려도 됩니다. **User-Agent 로 자동 분리**합니다 (예: kali-claude = `curl/8.8.0`, ARTEX = `norma/0.4`).

## 3. `attack_runs.csv` — 공격 실행 기록 (`ml/data/attack_runs.csv`)

```csv
tool,ip,start,end,result,ua,note
#도구(소문자: claude/artex/pentagi),공격PC IP,YYYY-MM-DD HH:MM (KST 날짜+시간),YYYY-MM-DD HH:MM (KST 날짜+시간),success/fail (선택),UA 일부 (선택),메모 (선택)
claude,192.168.0.27,2026-10-29 13:10,2026-10-29 14:22,,,kali-claude
claude,192.168.0.27,2026-10-29 14:23,2026-10-29 14:28,success,,kali-claude
artex,192.168.0.27,2026-10-29 13:53,2026-10-29 14:06,,,
artex,192.168.0.27,2026-10-29 14:19,2026-10-29 14:36,fail,,
```

| 컬럼 | 설명 |
|---|---|
| `tool` | 공격 계열. **소문자/숫자만** (`claude`, `artex`, `pentagi`). 세션 이름 맨 앞에 붙어 "처음 보는 도구" 평가 단위가 됨 |
| `ip` | 공격 PC IP |
| `start` / `end` | 실행 시작·종료 (KST, 분 단위면 충분. 앞뒤 1분 여유 자동 적용) |
| `result` | success / fail 등 (기록용) |
| `ua` | (선택) 자동 판단이 애매할 때 이 실행의 UA 일부 (예: `norma`) |
| `note` | 메모 |

- 2번째 줄(`#` 으로 시작)은 형식 안내라서 무시됩니다. 지우지 말고 그 아래에 한 줄씩 추가하세요.
- **start/end 는 날짜+시간 필수.** 시간만 쓰면 오류를 내고 멈춥니다 (`2026/10/29 13:10` 처럼 엑셀이 바꾼 형식도 인식).
- 엑셀로 열어 저장해도 됩니다 (UTF-8 / CP949 둘 다 읽음).

## 4. 자동 라벨링 규칙 (`build_label_rules.py`)

**공격** (`attack_runs.csv` 의 IP)
- UA 별로 묶고, **도구 하나만 실행 중이던 시간**에 그 UA 요청이 가장 많은 도구로 판단
- 실행 1회 = 세션 1개: `claude_1029_r1`, `artex_1029_r2` ...
- 그 UA 인데 실행 기록 밖의 요청 → `artex_1029_x1` 처럼 따로 넣고 **[확인 필요]** 출력 (`--drop-unlogged` 면 제외)
- 어느 실행 시간에도 없는 UA (1회성 curl 등) → 제외

**정상** (그 밖의 IP)
- (IP, UA) = 한 사람의 한 기기 = 세션 1개. manifest 가 있으면 `benign_m1_iphone`, 없으면 `benign_ip76_iphone`
- 제외: 브라우저가 아닌 UA, Claude 앱 브라우저(`Claude/`), 5건 미만 조각(서버 점검 요청), 5xx 20% 이상 조각(서버 장애 중)

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--buffer-min` | 1 | 공격 실행 앞뒤 여유(분) |
| `--gap-min` | 10 | 이 시간 넘게 끊기면 다른 조각 |
| `--min-requests` | 5 | 정상 조각 최소 요청 수 |
| `--max-5xx` | 0.2 | 이 비율 이상 5xx 인 정상 조각 제외 |
| `--exclude-ua` | `Claude/ HeadlessChrome python-requests` | 정상에서 뺄 UA |
| `--drop-unlogged` | 꺼짐 | 기록 밖 공격 요청 제외 |

출력의 **[제외]**, **[확인 필요]** 를 꼭 읽어보세요. 규칙표(`labels/*_rules.csv`)는 엑셀로 열어 고친 뒤 `--rules` 로 다시 쓸 수 있습니다.

## 6. 데이터는 얼마나, 파일은 몇 개?

- **피처 파일 개수는 상관없습니다.** 03 은 `features/` 의 `*_features.csv` 를 **전부 합쳐서** 학습합니다. 중요한 건 파일 수가 아니라 **세션 수**입니다.
- 수집 회차마다 파일이 하나씩 늘어나는 게 정상입니다 (`labeled_1029_...`, `labeled_1030_...`).
- **같은 시간대를 두 번 추출한 파일을 같이 두면 안 됩니다.** 같은 데이터가 학습과 검증에 동시에 들어가 점수가 부풀려집니다. 03 이 겹침을 찾으면 `[경고] 서로 다른 피처 파일에 같은 IP·시간 창이 겹칩니다` 를 출력합니다.

| 단계 | 조건 (세션 수) |
|---|---|
| 실행 가능 | 정상·공격 각각 2개 이상 |
| 결과 신뢰 | 각각 5개 이상, **공격 창 수백 개** 이상이면 오차가 크게 줄어듦 |
| 처음 보는 도구 평가 | 공격 도구 2종 이상, 도구별 세션 2개 이상 |

2026-10-29 기준: 정상 8세션/177창, 공격 5세션(claude 2, artex 3)/36창 → 돌아가지만 공격 데이터가 부족합니다.
